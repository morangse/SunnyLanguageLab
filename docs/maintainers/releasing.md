# 公开发行流程

## 公开快照

本次重写目录可单独使用 MIT 授权。公开仓库从新的初始提交开始，不把旧仓库、旧 ZIP、原型分支或私人归档历史一起公开。当前版本为 0.6.1 预览版。

1. 运行测试、双包打包、文档与来源状态检查；核对交付清单和第三方许可。
2. 扫描源码、示例、工作流和产物，排除凭据、签名、用户词库、本机依赖与数据库。
3. 将新的筛选快照推入公开仓库。设置 About、教程入口、安全报告功能。
4. 手动运行 Actions，或在版本提交中使用 `[build-ios]` 启动 iOS 编译；确认宿主应用内有 Safari 扩展，包声明支持两种设备。
5. 版本标签构建通过后，先创建草稿预发行版；核对文件、SHA256、签名要求与真实验证范围再发布。
6. 社交文案只使用已存在且可公开访问的仓库 / 发行链接，不把模拟图写成真机截图。

新代码仍需真机测试。iPhone 继续标为实验支持，Mac Safari 无完整安装包时继续写开发者路线。Cloudflare dry-run 不等于部署。

## 发布已经验收的构建

`Publish reviewed Sunny preview` 可复用已经成功的 main 构建，避免手动下载再上传。维护者核对构建后，在 `docs/releases/preview.json` 指定标签、完整构建提交与 run ID，提供同名 Markdown 发行说明，再手动运行此工作流；也可在 main 的发布配置提交中明确使用 `[publish-preview]` 触发。

普通代码推送不会触发公开发布。工作流检查构建成功、来自本仓库 main、运行代码与构建提交一致，并核对四个附件的版本、离线数据、许可与 iPhone / iPad 声明，生成 SHA256 后才创建公开预发行版。标签指向原构建提交，已有版本不会被覆盖。构建记录与真机验证应分别说明。
